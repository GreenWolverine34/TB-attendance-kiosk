# Google Sheets (Raspberry Pi / headless)

The project used to include Google Apps Script helpers, but for headless deployments (for example on a Raspberry Pi) the Apps Script files are not required.

This document explains the minimal spreadsheet and environment setup for running the kiosk app on a Pi and syncing check-in data directly to Google Sheets.

What the app now writes

- The app appends CSV rows to a sheet/tab named `rawData` in the target Google Spreadsheet.
- Each appended row has these columns (CSV header): `first_name,last_name,date,total_hours` (hours as a decimal number).

Quick setup on a Raspberry Pi

1. Create a Google Sheet and add a tab named `rawData`.
   - In the first row (header) place: First Name, Last Name, Date, Total Hours

2. Create a Google service account and grant it edit access to your Google Sheet.
   - Download the service account JSON key file.
   - Copy the JSON content and set it as an environment variable on the Pi named `GOOGLE_SERVICE_ACCOUNT_JSON` (the JSON must be a single string; if you put it in a file, ensure newlines are preserved when exporting into the env var).

3. Set the target spreadsheet ID in an environment variable named `GOOGLE_SHEET_ID`.
   - The spreadsheet ID is the long identifier in the sheet URL: https://docs.google.com/spreadsheets/d/<SPREADSHEET_ID>/edit

4. Install dependencies and run the kiosk app on the Pi.

   Example (on the Pi):

   - Clone this repo on the device.
   - From the repository root:
     - npm ci
     - npm run start

   Note: This project is an Electron app. On some Pi models you may prefer building a headless/node-only helper to run the sync; if so see "Headless sync helper" below.

Headless sync helper (optional)

- If running Electron on the Pi is not desired, a small Node process can be created to call the existing uploadReportsToSheet function and push CSV generated by the app into the sheet. You can re-use the logic in `src/sheets.ts` and `src/report.ts` to produce CSV and call the Google Sheets API.

Security

- Do not check service account JSON into source control. Keep `GOOGLE_SERVICE_ACCOUNT_JSON` and `GOOGLE_SHEET_ID` private on the device.

Troubleshooting

- If uploads fail, check that the service account has Editor access to the spreadsheet and that the `GOOGLE_SERVICE_ACCOUNT_JSON` contains a valid private key (preserve newlines; replace `\n` with actual newlines if needed when loading from a file).
- Linting or build warnings in the repo do not affect the spreadsheet sync directly but may indicate other issues.
